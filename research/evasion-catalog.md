# RepoGate — Evasion Catalog

**Date:** 2026-11-20 · **Method:** line-by-line reading of `repogate.py` v0.1.0 as written, cross-checked against `research/best-practices-2026.md` §5/§3 and the two tool audits in this folder (`tool-audit-nvidia-datadog.md`, `tool-audit-specialized.md`). No scanner code was modified.

**The six audited tools, short names used in the table:**
**SkSp** = NVIDIA SkillSpector · **GDog** = DataDog GuardDog · **CGuard** = tharun208/cloneguard · **Sigil** = NOMARJ/sigil · **RGuard** = WBChain3/repo-guard · **SRepo** = ScanRepo

**Evidence tags in the "Defeats" column:**
- **[D]** documented — a published bypass, the vendor's own docs, or a dated incident writeup
- **[A]** architecture — follows directly from the tool's audited scope/design (not a published exploit)
- **[I]** inferred — plausible from stated design; rules not public enough to confirm

**RepoGate v1 status:** **CATCHES** (a rule/mechanism fires on the technique as written) · **PARTIAL** (fires on some variants, or flags presence without analyzing content, or fails closed without identifying the payload) · **MISSES** (no rule or mechanism engages). Rule IDs and function names below are quoted from `repogate.py` so each verdict can be re-checked against the code.

**Cost key (rough solo-dev estimates):** S = hours–1 day · M = 2–4 days · L = 1–2 weeks.

## Notes on the highest-risk rows

**Row 14 is the only row where the target attacks RepoGate itself.** Every other row is about a payload evading *detection*; an uncapped, prefix-checked tar extraction is a payload attacking the *scanner's host* — the exact failure class GuardDog sandboxed against and Sigil shipped (and retracted) in production. The quarantine directory limits the blast radius to disk-fill and sibling-directory writes, but `acquire()` runs before any verdict exists, so "we scan before we clone" does not protect the scan step itself. Fix this before any other hardening: it is also the cheapest fix in the catalog (S).

**Row 16 is the only silent CLEAN.** Most misses in this catalog at least leave the payload's *ingredients* visible as isolated findings. A symlinked directory leaves nothing: no finding, no coverage dent, no skipped-file entry. It converts RepoGate's headline design win over SkillSpector ("we don't exclude directories") into a false statement for any tree that uses symlinks — which monorepos and npm workspaces routinely do.

**Row 19 is the bypass a competent attacker reaches for first.** It requires no obfuscation, no encoding, and no exotic format — just ordinary code organization. It is also the row where RepoGate is *stricter on paper* than GuardDog (GuardDog at least forms the cross-file risk at downgraded severity; RepoGate forms nothing). The fix is correspondingly the highest-value detection change available.

**Row 5's normalized-text gap is a one-line-class bug with outsized effect.** `decoded_variants(text)` is called on the raw text only. The entire point of `normalize()` is that attackers split things; a split base64 blob is exactly the case where decoding matters most, and it is precisely the case v1 doesn't decode. (Split *keyword* strings are covered — the folded variant is rule-scanned — which makes the omission easy to overlook.)

**Row 7 is a pure absence, not a weakness.** There is no gating code to evade; the category doesn't exist in v1. Because gating is also a *chain ingredient* in real droppers (fetch + sleep + CI-check), adding it improves rows 7, 8, and 19 simultaneously.

**What v1 already gets right (so fixes don't regress it):** the verdict path is fully deterministic (row 11 is a non-issue by construction); no directory exclusions (row 1); partial coverage fails closed to INCONCLUSIVE (row 13's safe half); the documented Checkmarx `getattr` shape is caught (row 6); Tags-block content is decoded and rescanned (row 10's strong half); shipped bytecode is at least presence-flagged (row 2). The catalog's PARTIAL verdicts mostly mean "the mechanism exists and one variant class escapes it," not "nothing is there."

**Dead code worth knowing about:** `shannon_entropy()` is defined in `repogate.py` and never called — there is no entropy rule in v1 despite the helper's presence (best-practices RG-OBF-001/005 assume one). Wiring it up (per-line and per-blob entropy as an obfuscation signal) is a small addition that supports rows 4, 5, and 13.

## Top 10 fixes, ranked by risk-reduction per unit of effort

1. **Archive hardening (row 14) — S.** Member-iteration caps (uncompressed size, ratio, count), `Path.is_relative_to` instead of string-prefix checks, explicit `filter="data"` for tar. *Why first:* it's the only fix that protects the scanner's own host, it's a few lines, and every other row assumes the scan step itself is safe.
2. **Gating rule family (row 7) — S.** CI/hostname/user/date checks and sleep/timer co-location as findings + chain ingredients. *Why:* closes a total blind spot (zero coverage today) with plain regexes, and strengthens the dropper chains in rows 8/19.
3. **Symlinked-directory coverage (row 16) — S.** Descend safely or report as unscanned surface counted against coverage. *Why:* eliminates the only silent-CLEAN hole and restores the truth of the "no excluded dirs" claim.
4. **Fetch-primitive evidence + instruction-by-URL (row 8) — S.** Any outbound fetch counts as network evidence for chains; external-instruction references in agent docs are findings. *Why:* two small rule changes that complete chains in rows 8, 19, and 20 simultaneously — the highest chain-completion leverage in the catalog.
5. **Git surface rules (row 17) — S.** `.gitmodules` URL checks, `.gitattributes` filter-driver flag, LFS-pointer flag. *Why:* three tiny structural checks covering the exact moment (clone) that RepoGate's verdict is used to authorize.
6. **Decode the normalized text + recurse (row 5, with row 10's presence rule) — M.** Run `decoded_variants` on raw *and* normalized text, recurse to depth 2, accept wrapped/URL-safe base64, add hex/rot13; add Tags-range chars to `obf-unicode-hidden`. *Why:* fixes a near-one-line omission that currently exempts the single most common obfuscation composition (split + encoded).
7. **Cross-file chains (row 19) — M.** Package-level stealer/dropper chains (BLOCK for credential + webhook/raw-IP combos, downgraded otherwise). *Why:* the highest-value *detection* change — it removes the cheapest reliable bypass — ranked below the S items only on effort.
8. **Join/char-code folding (row 4) — M.** Decode `['e','v','a','l'].join('')`, `"".join(...)`, and `fromCharCode`/`chr()` arrays into rescanned variants. *Why:* converts three LOW "shape" findings into actual content verdicts; pairs with fix 6's decode pipeline.
9. **Hook-surface completion (row 20) — M.** Lifecycle delegation resolution (scan the bundled target as hook-reachable), pyproject build-backend check, `.pth` handling, Gradle/Maven/Composer structural checks. *Why:* install-time execution is the volume-leading vector in the 2026 data (best-practices §1.5), and v1 covers only npm + setup.py + build.rs + VS Code + devcontainer.
